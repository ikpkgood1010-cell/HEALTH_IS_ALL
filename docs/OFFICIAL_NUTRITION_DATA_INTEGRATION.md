# 공식 식품·영양 데이터 연동

## 목적

내장 식품 사전에 없는 일반 식품과 시판 제품도 사용자가 자연어로 입력하면 공식 데이터 후보를 찾아 확인하고, 선택한 1회 섭취량을 기준으로 영양소·식단점수·Exp·건강 정수를 계산한다.

## 데이터 우선순위

1. 농촌진흥청 국가표준식품성분 DB 10.4(2026): 국내 일반 식품과 조리 상태
2. 식품의약품안전처 식품영양성분 DB: 국내 가공식품·외식 제품
3. USDA FoodData Central: 국내 DB에서 찾기 어려운 해외·일반 식품의 보조 후보
4. 앱 내장 결정론적 카탈로그: 자주 쓰는 음식의 오프라인 대체 경로

공식 원문:

- [국가표준식품성분표 검색](https://www.nics.go.kr/food/kfi/fct/fctFoodSrch/list)
- [국가표준식품성분 OpenAPI 이용 안내](https://www.nics.go.kr/food/kfi/openapi/useGuidance)
- [식품의약품안전처 식품영양성분DB API](https://www.data.go.kr/data/15127578/openapi.do)
- [USDA FoodData Central API 안내](https://fdc.nal.usda.gov/api-guide/)

## 구현된 흐름

1. `POST /api/v1/health/text/analyze`가 내장 카탈로그로 먼저 분석한다.
2. 음식명을 찾지 못했고 공식 API 키가 하나라도 설정되어 있으면 데이터 공급자를 순서대로 검색한다.
3. 후보가 여러 개면 앱이 제품명·제조사·출처가 포함된 선택 카드를 표시한다.
4. 사용자가 후보와 섭취량을 확인하면 제공 기준량을 실제 섭취량으로 환산한다.
5. 상세 리뷰에 열량·탄수화물·단백질·지방·식이섬유, 추정 범위, 점수, 보상, 계산 출처를 함께 표시한다.

직접 검색용 API도 제공한다.

```text
GET /api/v1/nutrition/foods/search?q=<음식명 또는 제품명>&limit=5
```

## 환경 변수

```text
RDA_NUTRITION_API_KEY=
MFDS_FOOD_API_KEY=
USDA_FDC_API_KEY=
```

값은 `.env.example`이나 GitHub에 넣지 않는다. 로컬 비밀 환경 변수 또는 Render Dashboard의 Environment에만 저장한다. 아무 키도 없으면 기존 내장 카탈로그만 사용하며 API와 앱은 정상 동작한다.

## 안전·정확성 원칙

- 공급자 호출 제한 시간은 4초이며 한 공급자 장애가 전체 기록을 막지 않는다.
- 검색 결과를 자동 확정하지 않고 사용자에게 실제 제품·음식 후보를 선택하게 한다.
- 제공량과 실제 섭취량을 분리하고, 미확정 섭취량은 낮음·예상·높음 범위로 표시한다.
- 음식과 영양값을 찾지 못하면 임의 평균을 저장하지 않는다.
- USDA의 Energy 값은 kJ가 아니라 kcal 단위만 선택한다.
- API 응답에는 비밀 키나 원격 오류 전문을 포함하지 않는다.
- 데이터 출처는 계산 결과와 상세 리뷰에 보존한다.

## 현재 범위와 후속 확장

이번 구현은 내장 사전에서 단 하나도 찾지 못한 음식·제품 입력을 공식 후보 카드로 연결한다. 여러 종류의 미등록 제품이 한 문장에 섞였거나, 내장 식품과 미등록 제품이 한 문장에 함께 있는 경우에는 항목별 검색·병합 UI가 추가로 필요하다. 그 전까지는 해당 제품을 한 항목씩 기록하면 공식 후보 선택과 계산을 사용할 수 있다.

실서비스 사용 전에는 농촌진흥청 및 공공데이터포털에서 발급받은 키를 Render에 등록하고, 실제 한국어 제품 3종 이상으로 후보명·제공량·영양값을 대조한다. USDA의 `DEMO_KEY`는 개발 확인용 호출 제한 키이므로 운영 키로 사용하지 않는다.
