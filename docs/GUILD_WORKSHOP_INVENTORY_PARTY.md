# 길드 제작소·인벤토리·용사 파티 MVP

## 기능 범위

건강 기록으로 얻은 길드 주화를 수집형 제작에 사용하고, 합류한 용사를 원정대 슬롯에
배치한다. 제작품과 파티 배치는 새로고침 후에도 서버 기록에서 복원된다.

## 제작법

| 코드 | 이름 | 비용 | 분류 | 능력치 효과 |
|---|---|---:|---|---|
| `FOREST_COMPASS` | 숲길 나침반 | 길드 주화 20 | 기념품 | 없음 |
| `WARM_TRAIL_CLOAK` | 포근한 길잡이 망토 | 길드 주화 40 | 의상 | 없음 |

- 첫 용사가 합류하기 전에는 제작소가 잠겨 있다.
- 각 제작품은 사용자당 한 번만 만들 수 있다.
- 같은 요청을 재시도하면 기존 제작품을 반환하고 주화를 다시 차감하지 않는다.
- 길드 주화는 현금 구매·확률형 뽑기·능력치 구매에 사용하지 않는다.

## 인벤토리

제작 완료 기록은 `game_craft` 이벤트로 영구 보관한다. 이름, 분류, 설명, 실제 지불
비용, 제작 시각과 `gameplay_effect=NONE`을 함께 저장한다. 현재 MVP에서는 판매,
분해, 강화, 거래를 지원하지 않는다.

## 파티 배치

- 첫 슬롯은 `VANGUARD(선봉)` 하나다.
- 실제로 합류한 용사만 배치할 수 있다.
- 같은 용사를 같은 슬롯에 재배치해도 이벤트를 중복 생성하지 않는다.
- 배치는 현재 전투력·보상 배율을 바꾸지 않는 원정대 구성 기록이다.

## 잔액과 동시성

보유 길드 주화는 `game_adventure_claim` 합계에서 `game_craft` 합계를 뺀 값이다.
제작 전에 사용자 프로필 행을 잠가 서로 다른 제작 요청이 동시에 잔액을 초과하지
않도록 한다. SQLite 테스트에서는 중복 ID 보호를, PostgreSQL 운영 환경에서는 행 잠금과
중복 ID 보호를 함께 사용한다.

## API

- `GET /api/v1/game/workshop/{user_id}`
- `POST /api/v1/game/workshop/{recipe_code}/craft`
- `GET /api/v1/game/party/{user_id}`
- `POST /api/v1/game/party/vanguard/assign`

이번 구현에는 DB migration, Supabase 운영 데이터 변경, Render 환경 변수 변경이 없다.
