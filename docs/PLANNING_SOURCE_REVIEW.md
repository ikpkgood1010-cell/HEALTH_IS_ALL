# HEALTH IS ALL 기획 자료 검토 기록

## 기준 우선순위

구현 판단은 아래 순서를 따른다.

1. `MASTER PROMPT V1~10` — 뒤 버전이 앞 버전을 보완하며, V10을 최우선 기준으로 사용
2. `TODO LIST` — 마스터 프롬프트 작성 과정에서 이미 확정한 결정
3. `개발기획 1~42 합본` — 마스터 프롬프트에 없는 세부 기획의 보충 기준
4. `개발기획 1~42 검토(클로드)` — 충돌·누락·실행 가능성 검토 참고
5. `타 게임 개발기획서` — HEALTH IS ALL에 맞게 재설계하기 위한 참고 자료
6. `참고 UI 3종` — 흰색·민트·큰 카드·넓은 여백의 토스형 표현 참고
7. `Spec 자료` — 운동 Enum과 개인화 회복 계산의 상세 기술 기준

같은 항목이 충돌하면 위쪽 자료가 우선한다. 따라서 HBI는 `Health Balance Index`이며
`최저 영역 × 0.6 + 전체 평균 × 0.4`로 계산한다.

## 확인한 핵심 확정 사항

- 서비스의 최우선 가치는 게임 성과가 아니라 건강 기록과 회복이다.
- 하단 탭은 `홈 / 운동 / 식단 / 길드 / 마이`의 정확히 5개다.
- UI 참고 이미지의 마스코트와 6개 탭 구성은 채택하지 않는다.
- 현재 MVP는 로그인 없는 익명 사용자로 진행한다.
- 소셜 로그인 후보는 향후 `KAKAO / NAVER / GOOGLE / APPLE`이지만 데이터 이전과
  복구 정책이 준비되기 전에는 노출하지 않는다.
- 회복 기준은 복부 24시간, 팔·전완 36시간, 가슴·어깨 48시간,
  등·하체 72시간이다.
- 운동은 대분류·27개 소분류·강도의 독립 필드로 기록한다.
- 개인화 회복시간은 기본 시간에 강도·컨디션·빈도·연령 계수를 곱한다.
- 정령 속성은 `FIRE / WATER / WIND / FOREST / LIGHT / MOON`, 기본은
  `FOREST`다.
- 살아있는 길드는 레벨 1/10/30/50/100에서 성장 단계를 바꾼다.
- 살아있는 던전, 보스, 모험 회상, 기억의 길, 명예의 전당은 장기 확장 기준이다.
- 활동이 적은 날을 비난하거나 획득 자원을 회수하는 설계는 금지한다.

## 참고 게임에서 가져온 원칙

다른 게임의 명칭·수치·화면을 그대로 복제하지 않고 다음 설계 원칙만 사용한다.

- 반복 조작보다 자동 진행과 마을의 시각적 성장에 집중
- 영웅은 뽑기가 아니라 스테이지·퀘스트·이벤트 구조로 합류
- 농장·낚시·집 꾸미기는 장기 체류용 보조 순환으로 단계적으로 개방
- 탑과 순환(환생)은 건강 기록을 초기화하지 않는 별도 게임 진행으로 제한
- 결제 재화와 확률형 뽑기는 현재 기획에서 제외

## UI 해석

참고 이미지 3장은 최종 시안이 아니라 분위기 기준이다. 구현에는 다음만 반영한다.

- 흰색 카드, 옅은 회색 배경, 민트색 주요 동작
- 제목과 핵심 수치는 크게, 설명은 짧게
- 카드 사이의 넓은 여백과 둥근 모서리
- 한 화면에서 건강 상태를 먼저 보여주고 게임은 그 결과로 설명

게임 전용 일러스트와 캐릭터 비주얼은 확정 자료가 없으므로 임의 제작하지 않는다.

## 범위에 대한 정직한 구분

이번 구현은 기획 전체를 한 번에 완성한 것이 아니라, 이후 확장이 기획과 충돌하지
않도록 핵심 규칙과 실제 실행 가능한 MVP 세로 단면을 만든 것이다. 농장·낚시·전투·
보스·길드 협동·명예의 전당 등은 규칙을 보존하되 별도 기능 구현이 필요하다.
