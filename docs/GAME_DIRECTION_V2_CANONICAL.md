# HEALTH IS ALL : 건강이 전부다 !! — 게임 방향 V2

상태: **CANONICAL / 2026-08-16**

이 문서는 새 Gemini 기획 대화 1·2·4·5·6·7·8, 해당 프롬프트, Stitch AI 에셋,
기존 Master Prompt V1~10·TODO·개발기획 1~42를 시간순으로 대조한 현재 게임 기준이다.
겹치는 기존 길드·12시간 자동 모험 기획보다 이 문서를 우선한다.

## 1. 제품 구조

- 공식 명칭: `HEALTH IS ALL : 건강이 전부다 !!`
- 건강 앱 하단 탭: `홈 / 운동 / 식단 / 마이` 4개
- 게임 입장: 홈 상단의 게임 카드
- 게임에 들어간 뒤 건강 앱 하단 탭은 숨긴다.
- 길드, 마을, 전투, 용사, 별자리, 정령, 제작, 환생, 명예의 전당은 모두 게임 내부 기능이다.
- 게임은 완전 방치형에 가까운 한 번 누르고 지켜보는 구조를 지향한다.
- 건강 증진은 게임의 동력이나, 게임 자체도 완성도 있는 독립 순환을 가져야 한다.
- 게임 런타임 아트는 실시간 3D가 아니라 `HD 픽셀아트 + 2D 고정 시점 자동전투`를
  사용한다. 고화질 Stitch 원화는 선택·상세·도감·전직 연출에 사용하고, 이동·전투는
  별도의 2D 스프라이트 애니메이션으로 표현한다.

## 2. 전투와 파티

- 싱글 플레이 기본 파티는 6명이다.
- 직군은 `탱커 / 전사 / 마법사 / 궁수 / 도적 / 치유사`로 고정한다.
- 용사는 전방으로 이동하며 전투하고, 층마다 일반방 5개와 보스방 1개를 순서대로 통과한다.
- 전투는 카드·덱·턴제가 아니라 전장 위 6인 동시 실시간 자동전투다. 캐릭터 초상 카드가
  공격하거나 카드 슬롯에서 순서를 기다리는 화면을 사용하지 않는다.
- 제한시간·카운트다운·턴 종료는 없다. 공격력·방어력·체력·공격속도·명중·회피·치명타·
  저항·이동속도·사거리·회복력·스킬 재사용 주기에 따라 실제 처치 시간이 달라진다.
- 탱커는 최전방, 전사·도적은 근접, 마법사·궁수는 각자의 최소·최대 사거리, 치유사는
  안전한 중후방을 자동으로 유지한다. 사거리 밖이면 접근하고 너무 가까우면 원거리와
  치유사가 재배치한다.
- 적을 빨리 처치하면 바로 다음 방으로 이동하고, 오래 걸리면 그만큼 늦게 돌파한다.
  전멸하면 해당 방에서 진행이 멈추며 `1/6~6/6` 표시는 시간이 아니라 방 번호다.
- 이동, 기본 공격, 대상 선택, 활성 스킬 사용은 자동이다.
- 활성 스킬은 최대 6개이며 자동 사용을 기본으로 한다.
- 전직마다 패시브 스킬 1개가 자동 추가된다.
- 수동 회피, 수동 차단, 강제 멀티플레이, 카드 덱 편성은 기본 순환에 넣지 않는다.

## 3. 별자리·용사 영입·전직

- 별자리 성장판은 360° 구조이며 0층부터 6층까지 총 7개 층이다.
- 승인된 원형 보드의 중앙 영역을 0계층, 바깥 동심원 6개를 1~6계층으로 사용한다.
- 배경에는 노드를 굽지 않고 Flutter가 계층별 노드와 상태를 정확히 배치한다.
- 게임 시작 시 6직업 중 첫 용사 1명을 자유 선택해 무료로 영입한다.
- 0계층에는 선택하지 않은 나머지 용사 5명에 대응하는 대형 노드가 정확히 5개 있다.
- 0계층 대형 노드는 남은 용사를 랜덤 없이 개별 영입한다.
- 1~6계층에는 용사별 전직 대형 노드가 계층마다 정확히 6개 있다.
- 1~6층 대형 노드는 각 용사를 개별 전직시킨다.
- 전직 시 해당 차수의 무기·방어구 외형과 기본 직업 능력치가 한꺼번에 적용된다.
- 용사 외형은 6직업 × 0~6차 × 남녀의 84장으로 준비하되, 전직 해금 단위는 성별 공용
  42개다. 하나의 전직을 해금하면 같은 직업·차수의 남녀 외형을 동시에 얻고, 전투에
  내보낼 외형은 성능 차이 없이 무료로 선택한다.
- 별도 장비 인벤토리나 장비 세트 파밍은 없다.
- 표현은 `전직 단계와 전직 전용 장비 외형 영구 보존`으로 통일한다.
- 소형·중형 노드는 층마다 수와 경로가 달라질 수 있는 회차용 성장 노드다.

## 4. 환생 규칙

환생은 반복 성장의 재미만 되돌리고, 사용자가 획득한 정체성과 수집 성과는 빼앗지 않는다.

| 환생 시 초기화 | 환생 후 영구 보존 |
|---|---|
| 탑 도달 층·현재 방 | 영입한 6인 용사 |
| 골드 | 용사별 최고 전직 차수 |
| 회차 전용 임시 버프 | 전직 전용 장비 외형 |
| 소형·중형 노드 | 대형 노드 |
|  | 스킬·아바타·정령 |
|  | 건강 정수·별의 파편·성좌의 인장·성흔·초월 특성 |

- 일반 소형·중형 노드는 회차 골드로 다시 해금한다. 성좌의 인장 환불 후 즉시 재클릭하는
  구조는 사용하지 않는다.
- 이전 회차의 투자 순서를 저장하고, 사용자가 켜면 골드가 모일 때 같은 순서로 자동 투자한다.
- 기능 해금 노드는 일반 중형 노드와 분리하며 성좌의 인장을 쓰고 영구 보존한다.
- 환생 보상은 `별의 파편 + 성좌의 인장 + 10종 성흔 선택권`이다.
- 성흔은 무작위 3개 중 하나를 고르며 자동 추천 1개를 강조한다. 유료 리롤은 사용하지 않는다.
- 사용자에게 보이는 RP 잔액·용어는 만들지 않고 회차 성과를 내부 계산해 재화를 직접 지급한다.

## 5. 정령·제작·확률 정책

- 정령은 노드에서 알을 확정 해금하고 건강 에너지로 부화기를 채운다.
- 정령 부화는 랜덤이 아니며 중복도 없다.
- 기본 표시 이름은 `정령`이고, 사용자가 이름을 바꿀 수 있다.
- 제작 대상은 스킬과 아바타다. 결과는 100% 확정이다.
- 영웅, 정령, 스킬, 아바타에 확률형 뽑기를 사용하지 않는다.
- P2W 및 유료 확률형 재화는 현재 범위에서 금지한다.
- 전직 장비는 완성 외형에 자동 적용하며 장비 인벤토리·장비 드롭을 만들지 않는다.
- 과거 `세트 돌파`는 골드를 쓰고 환생 시 초기화되는 `회차 훈련`으로 변경한다.
- 치장 장착 자체에는 전투 능력치를 묶지 않는다. 영구 치장 재화 `별빛 실`로 확정
  외형을 해금하고, 작은 영구 효과가 필요하면 장착 상태와 무관한 도감 보너스로 총량을 제한한다.

## 6. 건강 데이터와 게임의 경계

- 운동·식단·수분·회복 등 원본 건강 기록은 건강 앱 영역에만 저장·표시한다.
- 게임 노드나 인벤토리에 `운동 기록`, `식단 기록` 같은 항목을 만들지 않는다.
- 게임에는 원본 기록이 아니라 목표 대비 달성도에서 계산한 건강 정수·보정치만 전달한다.
- 걷기와 칼로리에 편중하지 않고 웨이트, 크로스핏, 하이록스, 케틀벨, 계단, 등산,
  수영 등 서로 다른 활동을 개인 목표·시간·강도 기준으로 정규화한다.
- 과도한 운동량을 더 큰 보상으로 유도하지 않는다. 목표 100% 이후 보상은 상한 또는
  급격한 체감 감소를 적용한다.
- 쉬는 날, 질병, 회복일에 재화를 빼앗거나 연속 기록을 처벌하지 않는다.

## 7. 계산 원칙

```text
활동 A, 수면 S, 수분 W, 식단 D, 회복 R은 각각 0~100의 기록 지표
표시용 건강점수 = 0.35A + 0.20S + 0.15W + 0.15D + 0.15R
목표 초과분 보상 = 100%까지 정상 증가, 이후 0 또는 강한 체감 감소
```

- 기록이 없는 항목은 건강하지 않다는 뜻의 0점이 아니라 `기록 없음`으로 표시한다.
- 건강점수는 소비하지 않는 설명용 지표이고, 전직에는 누적 재화인 건강 정수와
  별의 파편을 사용한다.
- 사용자 확정 수동 기록과 사용자 확정 AI 추출 기록은 기본 보상 100%를 받는다.
- AI confidence는 실제 정확도 확률이나 보상 승수로 사용하지 않는다.
- 운동 중 휴식은 더 짧을수록 보상하지 않고 계획한 휴식 범위 준수만 반영한다.
  심박은 높이에 비례시키지 않고 유효 기록 완결성만 반영하며 두 추가 보상 합계는
  세션 최대 5%와 일일 상한을 적용한다.
- 세부 안전·출처·미기록 처리 기준은 `HEALTH_SCORING_CANONICAL_REVISIONS.md`를 따른다.

실제 골드·별의 파편·환생 요구량은 콘텐츠 표와 시뮬레이션이 준비되기 전에는 운영값으로
확정하지 않는다. 현재 UI 수치는 배치 확인용 상태로만 취급한다.

## 8. 2D 아트·애니메이션 기준

- 전투는 오른쪽을 향하는 3/4 고정 시점으로 구현한다.
- MVP 동작은 대기 3, 이동 4, 기본 공격 4, 액티브 스킬 6, 피격 2, 승리 3,
  쓰러짐 3프레임을 시작 기준으로 한다.
- 배경은 정적 픽셀아트 2~3개 레이어의 느린 시차 이동으로 깊이를 표현한다.
- 자유 이동처럼 보이는 연출은 `접근 이동 → 정지 → 동작 재생 → 위치 보간`으로 만들고,
  실시간 3D 모델·Blender 리깅은 사용하지 않는다.
- 상세 제작·검수·파일 규격은 `GAME_2D_ART_AND_ANIMATION_PIPELINE.md`를 따른다.
- 과거 문서의 SD 3D·3D 디오라마·3D 전투 요청은 제작 이력일 뿐 현재 런타임 기준이 아니다.

## 9. 현재 구현 경계

- 구현됨: 4탭, 홈 게임 입장, 게임 내부 정보구조, canonical read-only API 계약
- 레거시 호환: 기존 12시간 자동 모험·길드 API는 deprecated 상태로 잠시 유지
- 구현됨: 영속 게임 상태, 첫 용사 무료 선택 API·화면, 안전한 환생 실행 기반
- 구현됨(DB 미적용): 서버 시간 기반 지속 자동전투, 5+1 방 진행, 멱등 정산, Flutter 실제 상태 화면
- 구현됨(DB 미적용): 0계층 용사별 소형 6·중형 2 경로, 골드 소비, 5개 대형 노드 확정 영입
- 후보값: 100층 자율 환생, 별의 파편 보상, 전투·노드 경제의 30회 환생 시뮬레이션 완료
- 구현됨(DB 미적용): 1~6계층 용사별 확정 전직 비용·외형·스킬 슬롯과 건강 기록→건강 정수 어댑터
- 미구현: 세부 전직 경로의 소형·중형 노드, 실제 패시브·액티브 전투 효과, 2D 전투 에셋 연결
- 원본 건강 데이터나 실제 Supabase 스키마를 이번 변경에서 수정하지 않는다.
