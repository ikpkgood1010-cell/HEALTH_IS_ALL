## 이번에 확정한 Runtime

- 첫 용사 영입 시점부터 서버 시간이 누적된다. 영입 전에는 전투 시간과 보상이 생기지 않는다.
- 한 층은 일반방 1~5번과 보스방 6번을 반드시 순서대로 지난다.
- 앱 재진입과 새로고침은 `POST /api/v1/game/battle/settle` 한 번으로 경과 시간을 정산한다.
- 클라이언트 시간이 아니라 DB에 저장한 서버 기준시각을 사용한다.
- 정산 UUID가 같으면 최초 결과를 그대로 반환해 방·층·골드를 중복 지급하지 않는다.
- 같은 사용자의 동시 정산은 프로필 행 잠금 뒤 멱등 로그를 다시 확인한다.
- 보상은 현재 회차 재화인 골드뿐이다. 건강 정수·별 조각·초월 포인트는 자동전투에서 만들지 않는다.
- 환생은 층·방·골드와 현재 방의 경과 시간을 초기화하고 새 서버 기준시각을 설정한다.

## 격리된 밸런스 후보

정확한 골드·노드 비용·환생 요구량은 아직 승인된 운영값이 아니다. 모든 후보 상수는
`backend/idle_battle_engine.py`의 `BattleTuning` 한 곳에 모았다.

| 항목 | 현재 후보 | 의미 |
|---|---:|---|
| 오프라인 인정 상한 | 12시간 | 한 번의 정산에서 인정하는 최대 서버 경과시간 |
| 영입 용사 기본 전투력 | 100 | 직업별 차등 전 단계의 공통값 |
| 전직 1단계 증가 | +40% | 해당 용사의 기본 전투력 기준 |
| 층 난이도 증가 | 층당 ×1.08 | 방 소요시간에 반영 |
| 일반방 기준시간 | 45초 | 1인·1층·무전직 기준 |
| 보스방 기준시간 | 90초 | 같은 조건의 보스 기준 |
| 일반방 골드 | `floor(8 × 층^0.7)` | 회차 골드 후보 |
| 보스방 골드 | `floor(35 × 층^0.7)` | 회차 골드 후보 |

방 시간은 최소·최대 안전선을 적용한다. 늦은 층에서 계산이 무한히 커지거나 잘못된
상수가 한 요청에서 무제한 반복을 만들지 않도록 지수와 반복 횟수에도 방어 상한이 있다.

`python scripts/simulate_idle_battle_balance.py`는 1시간 정산 구간을 30번 이어서 비교한다.

| 파티 | 30시간 후 위치 | 완료 방 | 완료 보스 | 골드 후보 |
|---|---:|---:|---:|---:|
| 첫 용사 1명·무전직 | 134층 4번 방 | 801 | 133 | 181,429 |
| 6명·무전직 | 153층 6번 방 | 917 | 152 | 227,955 |

이 결과는 전투 진행의 단조성·상한·결정성을 확인하는 **30개 정산 구간 비교**다. 기획이
요구한 **30회 환생 경제 시뮬레이션**은 소형·중형 노드 비용과 환생 조건이 정해진 뒤에만
가능하다. 따라서 위 숫자를 상품 가격, 운영 공지, 라이브 DB 기본값으로 확정하지 않는다.
