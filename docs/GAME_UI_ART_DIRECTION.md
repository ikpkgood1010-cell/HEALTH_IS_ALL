# HEALTH IS ALL UI·아트 적용 기준 V3

## 화면 분리

- 건강 앱과 게임: 32-bit 소프트 청키 픽셀도트 UI를 공통 기준으로 사용한다.
  짙은 남색·청록·따뜻한 황금색을 기본 팔레트로 하고, 건강 데이터는 픽셀 프레임 안에서도
  우선순위와 여백을 유지해 읽기 쉽게 배치한다.
- 게임: 짙은 남색·따뜻한 황금색의 SD 픽셀 판타지다. 흥미를 주되 전투·건강 기록·보상 정보가
  동시에 경쟁하지 않도록 한 화면의 주요 행동은 하나로 유지한다.
- 홈 상단 배너가 두 세계의 유일한 기본 진입점이다.
- 게임 입장 후 건강 하단 내비게이션을 숨기고 게임 내부 메뉴를 사용한다.

## 시각 원칙

- 특정 상용 게임을 복제하지 않고, 단단한 픽셀 외곽선·읽기 쉬운 실루엣·따뜻한 조명이라는
  감각만 참고한다.
- 용사 상세·도감·전투 모두 같은 32-bit HD 픽셀아트 세계관을 사용한다. 용사는 4.8~5.2등신
  비율을 기본으로 하고, 정령은 2~3등신을 기본 범위로 한다.
- 전투는 6인 직군의 위치와 역할이 한눈에 보이되 이펙트로 화면을 덮지 않는다.
- 전투 화면의 65~75%는 실제 픽셀 전장으로 사용한다. 여섯 용사는 카드나 초상 슬롯이
  아니라 전장 바닥 위의 전신 스프라이트로 동시에 움직인다.
- 카드 프레임, 덱 칸, 손패, 턴 표시, 행동 게이지, 제한시간 UI는 전투 화면에서 금지한다.
- 용사 상세·도감용 원화는 전투 스프라이트와 같은 캐릭터 특징·색상·장비 실루엣을 유지한
  정면 또는 3/4뷰 픽셀 초상으로 만든다. 1990년대 TV 만화풍, 어린이 동화책풍, 둔한 3등신,
  실사·3D 렌더링은 사용하지 않는다.
- 한 화면의 주요 행동은 1개, 보조 행동은 2개 이하를 우선한다.
- 생성 이미지에 한글·영문 문구·수치·버튼 라벨을 굽지 않고 Flutter 위젯으로 텍스트·버튼을
  올린다. 전체 화면 시안은 런타임 이미지가 아니라 레이아웃·색상·픽셀 프레임의 참고 자료다.
- 모션 줄이기, 큰 글자, 색상 외 상태 표시를 유지한다.

## 제작 순서

기능·배치 → 접근성·반응형 → P0 에셋 제작 → 에셋 검수 → 최종 아트 적용 순이다.
필요 에셋과 프롬프트는 `STITCH_AI_ASSET_REQUESTS.md`를 따른다.
