# 자동 모험·훈련장 MVP 구현 기준

## 구현 목적

건강 기록이 게임 진행으로 이어지는 첫 번째 실제 서버 저장 흐름이다. 앱을 반복해서 여는 행위가 보상이 되지 않도록 하고, 네트워크 재시도나 버튼 중복 입력에도 보상이 한 번만 지급되게 한다.

## 자동 모험 정산

- 사용자별로 가장 최근에 끝난 UTC 12시간 구간(00:00~12:00, 12:00~24:00)을 정산하며 구간마다 결과는 하나만 생성한다.
- 진행 중인 구간을 미리 확정하지 않으므로 앱을 일찍 열었다는 이유로 이후 건강 기록이 보상에서 빠지지 않는다.
- 모험 ID는 `사용자 + 구간 시작 시각`으로 만든 결정적 UUID이므로 같은 구간을 재조회해도 동일하다.
- 기존 건강 기록으로 계산한 활력·HBI·길드 주화를 사용한다.
- 자동 모험 효율은 확정 기획에 따라 70%다.
- 건강 상태가 낮아도 음수 보상이나 손실은 없다.
- 모험마다 5개 방 경로를 결정적으로 생성한다. 첫 방은 전투, 마지막 방은 보스,
  보스 직전은 휴식 또는 상점이며 나머지는 확정 가중치를 따른다.
- 탑 층수와 방 경로는 정산 이벤트의 `detail_json`에 함께 저장되므로 재조회해도
  같은 모험 이야기가 표시된다. 기존 정산 이벤트에는 같은 ID로 경로를 복원한다.
- 게임 이벤트는 기존 `activity_logs`에 append-only 방식으로 저장하며 이번 구현에는 DB migration이 없다.

## 보상 수령과 중복 방지

- 보상 수령 ID도 모험 ID에서 결정적으로 생성한다.
- 동일 보상 요청을 여러 번 보내면 최초 수령 결과를 반환하고 추가 지급하지 않는다.
- 다른 익명 사용자의 모험 ID로는 보상을 받을 수 없다.
- 동시 요청이 발생해도 DB 기본 키 충돌을 안전하게 처리해 하나의 수령 이벤트만 남긴다.

## 훈련장 1종

- 모험 보상 길드 주화의 20%를 훈련장에 자동 투자한다.
- 나머지 80%는 보유 길드 주화로 기록한다.
- 시설 레벨은 누적 투자량으로 계산한다.
  - Lv.1 → Lv.2: 100
  - 이후 레벨 요구량: 레벨마다 50 증가
- 초기 MVP에서는 시설이 추가 보상 배율을 만들지 않는다. 복리형 인플레이션을 막고 성장 진행도를 먼저 검증한다.
- 시설 레벨 1/3/6/10에서 들판 훈련터/나무 훈련장/돌담 연무장/수호자의
  훈련관으로 외형 설명이 바뀐다. 이 변화는 시각적 피드백이며 경제 배율은 없다.

## 최근 모험 회상

- 최근 저장된 모험을 최신순으로 최대 5개 표시한다.
- 회상은 저장된 `game_adventure` 이벤트만 읽고 정산·지급을 실행하지 않는다.
- 탑 층수, 마지막 방, 방 개수, 주화, 보상 수령 여부를 보여준다.

## 저장 이벤트

| `record_type` | 역할 | 중복 방지 키 |
|---|---|---|
| `game_adventure` | 12시간 모험 정산 결과 | 사용자 + 구간 시작 |
| `game_adventure_claim` | 보상 수령과 보유 주화 | 모험 ID |
| `game_facility_investment` | 훈련장 자동 투자 | 모험 ID |

게임 이벤트는 건강 연속 기록 계산에서 제외한다. 따라서 모험을 열거나 보상을 받아도 건강 streak가 늘어나지 않는다.

## API

- `POST /api/v1/game/adventures/settle`
- `POST /api/v1/game/adventures/{adventure_id}/claim`
- `GET /api/v1/game/facilities/training-grounds/{user_id}`
- `GET /api/v1/game/adventures/history/{user_id}?limit=5`

`AdventureResponse`는 `tower_floor`와 5개 `rooms(position, room_type, title,
outcome)`을 포함한다.

## 운영 안전선

- 이번 작업에서는 실제 Supabase 연결, 운영 데이터 생성, migration, Render 배포를 수행하지 않는다.
- SQLite 격리 테스트에서 정산·재시도·소유권·보상 보존을 검증한다.
- PR 병합 뒤 Render가 새 버전을 배포하면 길드 탭이 서버 API를 사용한다.
